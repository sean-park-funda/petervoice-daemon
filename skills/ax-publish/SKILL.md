# AX Publish — 만든 자동화를 대시보드에 발행

이 프로젝트에서 만든 자동화를 **AX 자동화 대시보드**(`https://www.peter-voice.site/ax`)에 올립니다.
실무자는 그 화면에서 "오늘 잘 돌았나 / 결과는 어디 있나 / 이것 좀 바꿔줘"를 하게 됩니다.

`/local-publish`가 만든 앱을 인터넷에 공개하는 것이라면, 이 스킬은 **만든 자동화를 대시보드에 공개**합니다.

## 전제 — 발행은 마지막 단계다

이 스킬은 **이미 동작하는 자동화가 있을 때** 씁니다. 순서는 이렇습니다.

1. 프로젝트를 만든다 ← 피터보이스 기본 기능
2. 그 안에서 자동화를 만들고 손으로 돌려본다 ← 평소 하던 작업
3. **발행한다 ← 이 스킬**

2번이 안 됐으면 발행하지 마세요. "먼저 한 번 손으로 돌려보고, 결과가 나오면 발행하시죠"라고 안내합니다.

## 작동 방식 (알고 있어야 오해가 없다)

이 스킬은 **파일 두 개만 만듭니다.** 웹 API를 직접 부르지 않습니다.

```
cron/<이름>.json      → 언제 어떤 명령을 돌릴지
.ax/workflow.json     → 대시보드에 뭐라고 보일지
```

호스트의 러너가 30초마다 이 파일들을 읽어서 대시보드에 반영합니다. 저장하면 잠시 뒤 자동으로 뜹니다.
**대시보드 채팅용 창구도 자동으로 만들어집니다** — 따로 할 일 없습니다.

정의 원본이 이 폴더 안에 있다는 것이 중요합니다. 나중에 고객사에 인계할 때 폴더째 넘기면 그대로 동작합니다.

## 발행 절차

### Step 1. 지금 위치 확인

```bash
pwd && ls
```

프로젝트 폴더 안이어야 합니다. `general`(기본프로젝트)에서는 발행하지 마세요 —
**자동화 1개는 프로젝트 1개**를 써야 합니다. 기본프로젝트에 있다면
"이 자동화 전용 프로젝트를 먼저 만드시죠"라고 안내하고 멈춥니다.

### Step 2. 사람에게 묻는다 (추측하지 말 것)

아래를 **한 번에 다 묻지 말고** 대화하듯 하나씩 확인합니다. 이미 대화에서 나온 건 다시 묻지 않습니다.

| 물을 것 | 예시 | 쓰이는 곳 |
|---|---|---|
| 이 자동화를 뭐라고 부를까요? | "뉴넥스 소식 모니터링" | 대시보드 카드 제목 |
| 뭘 하는 건지 한 줄로 | "매일 아침 뉴넥스 관련 기사를 모아 정리합니다" | 카드 설명 |
| 언제 돌릴까요? | "매일 아침 8시" | 실행 시각 |
| 실행할 명령은? | `node scrape/news.mjs --out data/latest.json` | 실제 실행 |
| 결과물은 어디서 보나요? | 링크 또는 파일 경로 | 산출물 버튼 |
| 담당자는 누구인가요? | "MD팀 · 김영훈" | 카드에 표시 |

**"언제"는 반드시 사람 말로 받고 여기서 변환합니다.** 사람에게 `0 8 * * *`을 묻지 마세요.

| 사람 말 | schedule |
|---|---|
| 매일 아침 8시 | `0 8 * * *` |
| 매일 오전 6시 30분 | `30 6 * * *` |
| 평일 오전 9시 | `0 9 * * 1-5` |
| 매주 수요일 오후 2시 | `0 14 * * 3` |
| 매시간 정각 | `0 * * * *` |
| 30분마다 | `*/30 * * * *` |

시간대는 **한국 시간(Asia/Seoul) 고정**입니다.

### Step 3. 폴더가 겹치지 않는지 확인

다른 자동화가 이미 같은 폴더를 쓰고 있으면 발행이 거부됩니다(대시보드가 409로 막습니다).
이 프로젝트 전용 폴더인지 확인하세요. 겹친다면 프로젝트를 새로 만들어야 합니다.

### Step 4. 실행 설정 파일 작성

```bash
mkdir -p cron .ax
```

`cron/<이름>.json` — 이름은 영문 소문자·하이픈으로 (`news-daily`):

```json
{
  "name": "news-daily",
  "schedule": "0 8 * * *",
  "command": "node scrape/news.mjs --out data/latest.json",
  "workdir": ".",
  "timeout_sec": 1800,
  "enabled": true
}
```

- `command`: 이 폴더 기준으로 실행됩니다. 손으로 돌려서 성공한 그 명령을 그대로 씁니다
- `timeout_sec`: 기본 1800(30분). 넘으면 강제 종료됩니다
- 단계가 여러 개면 파일을 여러 개 만듭니다 (`collect.json`, `report.json`) —
  실무자에게는 여전히 **자동화 1개**로 보이고, 안에서 단계별 성공/실패만 나뉩니다
- 여러 단계를 만들 때는 **실행 시각을 서로 벌려두세요.** 같은 시각에 몰리면 순서대로 대기합니다

### Step 5. 대시보드 표시 정보 작성

`.ax/workflow.json`:

```json
{
  "title": "뉴넥스 소식 모니터링",
  "description": "매일 아침 뉴넥스 관련 기사를 모아 정리합니다.",
  "owner_label": "MD팀 · 김영훈",
  "status": "draft",
  "outputs": [
    { "label": "오늘의 소식", "type": "url", "path": "https://example.com/news" }
  ]
}
```

- **`status`는 처음에 반드시 `draft`로 둡니다.** 실무자에게는 안 보이고 컨설턴트에게만 "준비중"으로 보입니다
- `outputs`의 `type`은 `url`(링크가 걸림) 또는 `file`(경로만 표시)
- `title`은 실무자가 읽을 이름입니다. 프로젝트 id를 그대로 쓰지 마세요

### Step 6. 흐름도 그리기 (중요)

**당신이 만든 자동화를 분해해서 그림으로 설명하는 단계입니다.** 이게 있어야 대시보드에
"어떻게 돌아가나"가 그려지고, 실무자가 자기 업무가 어디까지 자동이 됐는지 알 수 있습니다.

`.ax/workflow.json`에 `graph`를 추가합니다. n8n과 같은 `nodes` + `connections` 형식입니다.

```json
"graph": {
  "nodes": [
    { "id": "n1", "name": "매일 오전 8시", "type": "ax.trigger",
      "parameters": { "note": "정해진 시각에 스스로 시작합니다", "icon": "clock" } },
    { "id": "n2", "name": "기사 검색", "type": "ax.auto",
      "parameters": { "system": "구글 뉴스", "note": "검색어 3개로 훑습니다",
                      "batch": "news-daily", "icon": "web" } },
    { "id": "n3", "name": "읽고 판단", "type": "ax.human",
      "parameters": { "system": "담당자", "note": "무엇이 중요한지는 사람이 봅니다", "icon": "web" } }
  ],
  "connections": {
    "매일 오전 8시": { "main": [[{ "node": "기사 검색" }]] },
    "기사 검색":     { "main": [[{ "node": "읽고 판단" }]] }
  }
}
```

**노드 종류 — 이게 화면에서 색으로 갈립니다**

| `type` | 뜻 |
|---|---|
| `ax.trigger` | 시작 계기 (매일 몇 시 / 폼 제출) |
| `ax.auto` | **우리 자동화가 돌린다.** `batch`를 붙이면 오늘 성공/실패가 표시됨 |
| `ax.human` | 사람이 판단해야 하는 일 |
| `ax.external` | 고객·셀러 등 외부의 몫 |
| `ax.check` | 자동화 덕에 **새로 생긴 확인** (중복 차단, 정체 감지 등) |

**지킬 것**

1. **실제로 구현한 것만 그립니다.** 계획만 있고 없는 단계를 그리면 거짓말이 됩니다
2. `name`·`note`는 **비개발자가 읽을 문장으로**. `fetch_metrics()` ❌ → "지표 내려받기" ⭕
3. 사람이 하는 일·외부의 몫도 **빠뜨리지 않습니다.** 그래야 "손이 어디서 줄었는지"가 보입니다
4. 노드는 **5~12개**. 함수 단위로 쪼개면 40개가 되고 아무도 안 읽습니다
5. 실제로 도는 단계에는 **`batch`를 반드시 연결**합니다 (`cron/<이름>.json`의 `name`)
6. `connections`의 키는 **노드 `name`** 입니다 (id 아님)
7. 다 쓰고 나면 사람에게 **"이렇게 이해했는데 맞나요?"** 하고 확인받습니다

`icon`은 생략해도 되고, 쓰면 `sheet` `web` `chat` `admin` `doc` `check` `mail` `db` `clock` 중에서 고릅니다.

⚠️ **흐름도는 설명이지 실행 정의가 아닙니다.** 실행은 `cron/*.json`이 합니다.
나중에 자동화를 고치면 **흐름도도 같이 고쳐야** 합니다. 안 그러면 화면이 거짓말을 하게 됩니다.

### Step 7. 반영 확인

저장하고 30초쯤 기다린 뒤, 사람에게 이렇게 안내합니다.

> "준비중 상태로 올렸습니다. `www.peter-voice.site/ax`에서 확인하실 수 있습니다.
> 아직 실무자에게는 보이지 않습니다."

### Step 8. 한 번 돌려보고 정식 공개

먼저 `command`를 손으로 한 번 실행해 **결과물이 제대로 나오는지** 확인합니다.

```bash
python3 scrape/news.py   # cron/<이름>.json 의 command 를 그대로
```

⚠️ **손으로 돌린 실행은 대시보드에 기록되지 않습니다.** 대시보드에 찍히는 것은 정해진 시각에
자동으로 돈 것뿐입니다. 그러니 손으로 돌려 결과물만 확인하고, 대시보드의 첫 실행 기록은
예정된 시각이 지난 뒤에 확인하세요.

산출물이 정상이면 `.ax/workflow.json`의 `status`를 `active`로 바꿉니다.

```
"status": "active"
```

이때 사람에게 확인을 받으세요. **`active`가 되는 순간부터 실무자에게 보입니다.**

## 대시보드에서 내리기 (발행 취소)

"대시보드에서 내려줘", "이건 이제 안 써" 라고 하면:

1. `.ax/workflow.json`의 `status`를 `"draft"`로 되돌립니다 → 실무자 화면에서 사라집니다
2. 실행도 멈추려면 `cron/<이름>.json`의 `"enabled"`를 `false`로 바꿉니다

**파일을 지우지 마세요.** 지워도 대시보드에서 카드가 사라지지 않고, 기록만 잃습니다.
완전히 없애야 한다면 Sean에게 문의하세요.

## 실행 시각·명령 바꾸기

`cron/<이름>.json`을 고치면 30초 안에 반영됩니다. 별도 재발행이 필요 없습니다.
사람에게 바뀐 시각을 **사람 말로** 확인해 주세요 ("이제 매일 오전 7시에 돕니다").

## 에이전트 행동 가이드

- "대시보드에 올려줘" → Step 1~7 → **draft로 발행하고 멈춘다.** 함부로 `active`로 올리지 않는다
- "이제 공개해도 돼" → Step 8 (`active`로 승격)
- "내려줘" → `status`를 `draft`로
- "시간 바꿔줘" → `cron/*.json`의 `schedule`만 수정
- **자동화 내용을 고쳤다** → `.ax/workflow.json`의 `graph`도 같이 고친다 (안 그러면 화면이 거짓말을 한다)
- 기본프로젝트(`general`)에서 발행 요청 → 전용 프로젝트를 먼저 만들라고 안내하고 멈춘다
- 자동화가 아직 손으로도 안 돌아감 → 발행하지 말고 먼저 동작시킨다

## 화면에 나가는 말 (중요)

`title`·`description`·`outputs[].label`은 **비개발 실무자가 그대로 읽습니다.**

- 나쁨: `nunex-news-scraper`, "GraphQL 크롤러 배치"
- 좋음: "뉴넥스 소식 모니터링", "매일 아침 뉴넥스 관련 기사를 모아 정리합니다"

실행 결과 요약도 마찬가지입니다. 자동화 스크립트가 실패 메시지를 남길 때
로그가 아니라 사람 말로 남기게 만드세요 — 그 문장이 대시보드에 그대로 뜹니다.

- 나쁨: `Traceback (most recent call last): ConnectionError`
- 좋음: "다나와 접속이 막혀 12개 상품을 확인하지 못했습니다. 나머지 688개는 정상 처리됐습니다."

## 트러블슈팅

### 30초 넘게 기다려도 대시보드에 안 뜬다
- `status`가 `draft`인데 실무자 계정으로 보고 있진 않은지 (draft는 컨설턴트에게만 보임)
- JSON 문법 오류 — 파일 하나가 깨져도 다른 자동화는 계속 돕니다. `python3 -m json.tool <파일>`로 확인
- 다른 자동화와 같은 폴더를 쓰고 있는 경우 (Step 3)

### 카드는 뜨는데 오른쪽 채팅이 비활성이다
대화 창구가 아직 안 만들어진 경우입니다. 잠시 뒤 다시 확인하고, 계속 그러면 Sean에게 문의하세요.

### 실행이 안 된다
- `enabled`가 `false`는 아닌지
- `command`를 이 폴더에서 손으로 실행하면 되는지 (경로는 이 폴더 기준입니다)
- 앞 회차가 아직 안 끝났으면 이번 회차는 건너뜁니다 — 겹치지 않게 시간을 벌리세요

### "지금 한 번 돌려줘" 라고 한다
대시보드에는 아직 [지금 실행] 버튼이 없습니다. 명령을 손으로 실행해 드릴 수는 있지만
**그 실행은 대시보드 기록에 남지 않는다**는 점을 함께 알려주세요.
결과물만 바로 확인해 드리고, 기록은 다음 예정 시각에 남습니다.
