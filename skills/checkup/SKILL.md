# 사용 검진 (닥터) — 1단계

유저는 모르는 기능을 요청하지 못한다. "당연히 되겠지 → 안 됨 → 멍청하다"로 끝난 과제를 **이 계정 안에서** 다시 찾아
"이렇게 하면 됐다"를 같은 과제로 보여 주는 것이 이 스킬의 일이다. (설계: peter-voice `docs/plans/2026-10-06-usage-checkup-agent.md`)

## 원칙
- **이 계정의 데이터만** 읽는다(대화·프로젝트·브랜치·하트비트·BP 상태·프롬프트 길이·설치 스킬·연결 서비스 유무). 밖으로 보내지 않는다.
- 보고서에 대화 원문을 길게 옮기지 않는다 — 120자 발췌와 링크만.
- **자동으로 바꾸지 않는다.** 처방의 [적용]은 유저가 고른다(모델 변경·프롬프트 추가·BP 적용·스킬 사용 전부). 유저 결정은 한 번에 1~3개.
- 처방은 새로 지어내지 않는다 — 위키(confirmed)·BP 카드·헬프 시트에 있는 것만. 근거 없는 "더 나은 방법"은 소음이다.

## 절차
1. 초안 생성 (현재 프로젝트 디렉토리에서):
   ```bash
   python3 ~/.claude/skills/checkup/scripts/checkup.py --days 30
   # → docs/checkup/<오늘>.md 초안 + 요약 JSON 한 줄. 항목이 많으면(브랜치 300개+) 2~4분.
   ```
   클라우드 컨테이너에서 config.json 이 없으면 `PV_API_URL`·`PV_API_KEY` 환경변수를 쓴다.
2. 초안을 읽고 **판단을 덧붙인다** — 특히:
   - 1축(못 푼 과제): 공통 검색 후보가 정말 그 과제의 답인지 가른다. 아니면 「해당 없음」으로 지운다. 맞으면 그 페이지를 읽고
     **같은 과제를 지금 다시 해 본다**(비용이 작을 때). 전후 결과를 표 아래에 나란히 적는다 — 이것이 "비교 적용"이다.
   - 2축(기능 미사용): 연결만 된 서비스·안 쓴 스킬은 **이 유저의 대화에서 쓸 자리가 있었던 것만** 고르고, 유저 과제에 맞춘 예시 요청문 1개를 붙인다.
   - 4축(단일 vs 멀티): 메시지가 많아도 주제가 하나면 해당 없음. 주제가 둘 이상이면 어떤 담당자로 나눌지 이름까지 제안.
   - 6축(설정): 구형·소형 모델 고정, 추론 강도 없음, 공통 프롬프트 2,000자 미만, BP 미적용 — 바꿀 값과 바꾸는 자리(프로젝트 설정 > 엔진 & 모델 / 설정 > Best Practice)를 적는다.
   - 조회 실패(`🔴`)는 0건이 아니다 — 부록에 남기고 유저에게 "이 부분은 확인 못 했다"고 말한다.
3. 「요약」 절을 채운다: 결정 후보 **1~3개**, 각각 「무엇을 → 왜(근거 링크) → [적용]하면 무엇이 바뀌나」 한 줄씩. 기본값을 붙인다("답 없으면 1번만 적용").
4. 유저에게 보고: 채팅에는 **요약 5줄 + 보고서 경로(`docs/checkup/<날짜>.md`) + 결정 1~3개**만. 표를 채팅에 옮기지 않는다.
5. 유저가 고르면 그 자리에서 적용한다 — 모델/강도는 `PUT /api/projects {"id":…,"model":…,"effort":…}`, 프롬프트 규칙은 `PUT /api/prompts`(기존 내용 보존), BP 는 카드의 Setup 절차, 서비스·스킬은 예시 요청을 바로 수행. 적용 결과를 보고서 끝 「적용 기록」에 한 줄.

## BP 처방 — 베스트 프랙티스는 검진 규칙이다 (2026-10-07 Sean 결정)
스크립트가 `/api/bp/list` 의 `detect`(신호·처방·예시 요청)를 읽어 **신호가 보인 카드만** 「BP 처방」 절에 올린다. **보고서 처방 상한은 3개** — 많으면 읽을거리가 된다.
- 자동 탐지 카드: 로그인 인계 · 과거 대화 읽어보기 · 담당자 나눠 시키기 · 부사장 관리 · 릴레이 · 공유 허브 · 경로 데이터. 근거 발췌가 붙어 나온다 — 발췌가 정말 그 신호인지 담당자가 가른다(아니면 지운다).
- 담당자 판단 카드: 대화·문서 기억화 · 리서치 교차검증 — 1축 발췌와 조사형 대화를 열어 **근거 2개 이상**일 때만 더한다.
- 유저가 「처방 N 적용해줘」라고 하면: `GET /api/bp/doc?id=<id>` 로 카드를 읽고 **Setup 을 그대로** 실행한 뒤 Report 형식으로 `POST /api/bp/status` 에 상태를 보고한다. 설정 변경(프롬프트 한 줄·스킬 사용)은 바로, 외부 연결·비용이 드는 것은 한 번 더 확인.
- 카드 Setup 이 이 환경에서 안 되면 Degrade 절을 따르고 `unavailable` 로 보고한다. 추측으로 "적용됨"이라 하지 않는다.

## 월간 팝업에서 올 때 (2026-10-07)
피터보이스 웹은 매달 한 번 「이번 달 사용 검진을 할까요?」 팝업을 띄우고, 유저가 「지금 검진 시작」을 누르면 **기본 프로젝트** 채팅에
「이번 달 사용 검진을 시작해줘」가 유저 메시지로 들어온다. 유저가 직접 친 것과 똑같이 처리한다 — 그 문장은 언제든 다시 쳐도 같은 검진이 돈다는 것을
유저가 배우게 하려고 팝업이 문장을 그대로 보여 준다. 보고 끝에 한 줄: "같은 문장을 언제든 보내시면 다시 검진합니다."
같은 달에 이미 보고서가 있으면 새로 돌리지 말고 「지난번 처방 중 적용된 것 / 안 된 것」을 먼저 적고, 바뀐 것만 다시 본다.

## 주기
- 유저가 부를 때. 월 1회 하트비트에 넣으려면 `docs/HEARTBEAT.md` 에 "매월 N일 검진 1회(지난 보고서와 비교, 결정 1~3개)" 한 줄 — 유저 동의 후.
- 같은 달에 두 번 돌리지 않는다. 직전 보고서가 있으면 「지난번 처방 중 적용된 것 / 안 된 것」부터 적는다.

## 하지 말 것
- 다른 유저·다른 계정의 데이터를 조회하는 것 (API 키가 곧 범위다 — 넘어갈 수 없고 시도도 하지 않는다)
- 처방을 유저 동의 없이 적용하는 것, 보고서를 릴레이로 다른 담당자에게 보내는 것
- "더 잘 쓸 수 있다"를 근거 없이 말하는 것 — 모든 처방에 위키 id·BP id·시트 id 중 하나가 붙는다
