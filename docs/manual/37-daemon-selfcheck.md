# 37. 클라우드/전용 호스트 데몬 자가진단 (`데몬 진단`)

SSH 없이 **채팅만으로** 데몬 상태를 확인하는 기능. 2026-08-25 도입 (뉴넥스 사내 서버처럼 SSH가 자주 닫히는 전용 호스트를 위해).
claude 턴을 돌리지 않고 데몬 프로세스가 직접 리포트를 만들어 답한다 — **턴을 소비하지 않는다.**

## 사용법
채팅(어느 프로젝트/브랜치든)에 아래 중 하나를 그대로 입력:
- `데몬 진단` · `/진단` · `/selfcheck`
- 다른 문장 안에 `[[pv/selfcheck]]` 마커를 포함

1분 내에 리포트가 답으로 온다. 외부 릴레이(`[외부 relay @핸들]`)로 들어온 요청이면 **보낸 핸들에게도 같은 리포트를 자동 회신**한다 (Sean 측 인프라 담당이 원격 진단할 때).

## 리포트 항목
| 항목 | 보는 이유 |
|---|---|
| 데몬 코드 커밋·브랜치 | 자동배포가 실제로 반영됐는지 (전용 호스트는 `stable`, 공용은 `main`) |
| 서비스 상태·기동 시각·PID | 재시작 루프·장기 미재시작 |
| load / 메모리 / 디스크 | 자원 고갈 |
| 설정 요약 (키 제외) | 상한·컨테이너 모드·전용 여부 |
| 중앙 API 폴링 | 박스와의 연결, 대기 중 새로고침 요청 |
| 사용량 수집 상태 | **배너 갱신 문제의 핵심** — 마지막 시도, 새로고침 플래그, 로그인 여부, 지금 `/usage` 프로브를 실제로 돌린 결과 |
| 실행 중 턴 + 고아 유닛 | 이전 데몬이 남긴 `pvturn-*` (같은 작업 2회 실행 위험) |
| 최근 3h `[usage]` 로그 / 오류·경고 | 원인 추적 |

비밀값(키·토큰)은 출력에서 자동 마스킹된다.

## 읽는 법 (자주 있는 패턴)
- **배너가 안 바뀜**: "지금 /usage 프로브: 실패(None)" 이면 클로드 CLI 쪽(미로그인·세션 한도·컨테이너 정지). "OK" 인데 `updated_at` 이 옛날이면 사용량 스레드가 멈춘 것 → 데몬 재시작.
- **코드 커밋이 오래됨**: 자동배포 정지(`.deploy-pause`) 또는 브랜치 불일치(`stable` 미승격).
- **고아 유닛 ⚠️**: 배포 재시작 중 강제 종료된 턴. `sudo systemctl stop <유닛>` 으로 정리 (운영자).

## 구현 위치
`scripts/cloud_daemon.py` — `is_selfcheck_trigger()`, `selfcheck_report()`, `Worker.process()` 초입 인터셉트.
