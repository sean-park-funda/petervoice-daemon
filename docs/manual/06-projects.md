# 06. 프로젝트 관리

## 개요

Peter Voice는 멀티프로젝트 구조. 하나의 유저 계정에 여러 프로젝트가 있고, 각 프로젝트는 독립적인 Claude Code 세션, 디렉토리, 프롬프트, 환경을 가짐.

## 프로젝트 데이터 구조

```sql
projects (user_id, id)
├── id             — 프로젝트 식별자 (예: "peter-voice", "thegrim")
├── name           — 표시 이름
├── directory      — 로컬 디렉토리 경로
├── deploy_url     — Vercel 배포 URL
├── chrome         — 브라우저 자동화 사용 여부
├── account        — Claude 계정 (멀티 계정)
├── model          — Claude 모델 오버라이드
├── session_summary — 세션 간 컨텍스트 요약
├── parent_project — 브랜치 원본 프로젝트
├── kanban_enabled — 칸반 보드 활성화 여부
├── team_id        — 연결된 팀 (칸반 활성화 시 자동 생성)
└── max_concurrent_kanban — 동시 칸반 세션 수 제한 (기본 3)
```

## API 엔드포인트

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | /api/projects | 전체 프로젝트 목록 |
| POST | /api/projects | 프로젝트 생성 |
| PUT | /api/projects | 프로젝트 수정 |
| DELETE | /api/projects | 프로젝트 삭제 ("general" 삭제 불가) |
| GET | /api/projects/activity | 프로젝트별 활동 정보 |
| POST | /api/projects/activity | 조회 시각 기록 |
| POST | /api/projects/branch | 프로젝트 브랜치 |

## 프로젝트 드롭다운 UI

헤더 중앙의 프로젝트명 클릭 → 드롭다운 다이얼로그

### 표시 정보

```
┌──────────────────────────────────┐
│ 🔄 peter-voice (현재)            │  ← 파란 보더
│   "커밋하고 푸시했습니다"  1분 전  │  ← 마지막 메시지
├──────────────────────────────────┤
│ ● thegrim                        │  ← 🔴 unread 표시
│   "구현 완료했습니다"  5분 전      │  ← 하이라이트 (1시간 내)
├──────────────────────────────────┤
│   signalflow                     │
│   "테스트 통과"  3시간 전         │  ← 일반
├──────────────────────────────────┤
│   cocktail                       │
│   "수정했습니다"  2일 전          │  ← 일반
└──────────────────────────────────┘
```

### 정렬 기준

1. 현재 프로젝트 (최상단, 파란 보더)
2. 최근 대화순 (각 프로젝트의 마지막 메시지 시각)
3. "demo_" 접두사 프로젝트는 데몬에서 별도 처리 (데모 모드: max_turns 3, `_demo` 프롬프트)

### 하이라이트 로직

- **노란 하이라이트**: 최근 1시간 이내 대화가 있는 프로젝트
- **Unread 빨간점**: 내가 아직 안 읽은 봇 응답이 있는 프로젝트
- **현재 프로젝트**: 파란 보더 (하이라이트와 독립)

### Unread 추적

```
봇 응답 도착 (messages INSERT, type='bot')
  ↓
project_views.last_viewed_at과 비교
  ↓
message.created_at > last_viewed_at → unread
  ↓
프로젝트 드롭다운에 빨간점 표시
  ↓
해당 프로젝트 진입 시 → POST /api/projects/activity → last_viewed_at 갱신
```

**DB 기반 추적** (로컬스토리지 아님): 핸드폰/노트북 등 여러 디바이스에서 일관성 유지

### 실행 상태 표시

- 데몬이 Claude Code를 실행 중인 프로젝트: 회전 스피너 아이콘
- 해당 프로젝트 선택 시에도 헤더에 스피너 표시
- 다른 프로젝트에서는 헤더 스피너 미표시

## 프로젝트 설정

헤더의 프로젝트명 옆 설정 아이콘 클릭:

| 설정 | 설명 |
|------|------|
| 이름 | 프로젝트 표시 이름 |
| 디렉토리 | 로컬 코드 경로 |
| 배포 URL | Vercel 등 배포된 URL (클릭으로 이동) |
| 계정 | Claude 계정 선택 |
| 모델 | Claude 모델 오버라이드 |
| 프롬프트 | 프로젝트별 + 공통 시스템 프롬프트 편집 |

## 프로젝트 브랜치

기존 프로젝트에서 파생된 새 프로젝트 생성:
- 부모 프로젝트의 세션 요약 계승
- 새 프로젝트 ID, 이름 지정
- 독립적인 세션으로 동작

## 사이드바 브랜치 표시 개선

### 오래된 브랜치 자동 숨기기

2일 이상 대화가 없는 브랜치는 자동으로 숨겨지고, **"N개 더보기"** 버튼으로 접힌다. 현재 선택 중이거나, unread가 있거나, 최근 활동이 있는 브랜치만 기본 표시.

### 브랜치 정렬 기준

1. **현재 선택** (최상단)
2. **unread** (안 읽은 응답이 있는 브랜치)
3. **최근 대화 시간순**

### 프로젝트 접기/펼치기

브랜치가 있는 프로젝트 이름 왼쪽에 **chevron(▾)** 아이콘 표시. 클릭하면 해당 프로젝트의 브랜치 목록을 접거나 펼 수 있다.

### unread 미리보기

- **unread 브랜치**: 제목 + 시간 + 최근 대화 내용 미리보기 텍스트
- **읽은 브랜치**: 제목 + 시간만 표시 (미리보기 없음)

### 프로젝트 최근 활동 하이라이트

1시간 이내에 활동이 있는 프로젝트에 **노란 배경** 표시. 프로젝트 메인 대화와 브랜치 대화 활동을 각각 독립적으로 판단.

### 최근순에서 하위 브랜치 숨기기/보이기 (담당자 명령, 2026-08-29)
담당자(브랜치)가 많은 프로젝트는 릴레이 답장("했습니다")만으로 최근순 탭이 파란 점 브랜치로 도배된다. 유저가 프로젝트 담당자에게 "하위 브랜치들 최근 목록에서 빼줘/넣어줘"라고 시키면 에이전트가 `POST /api/recent-hidden`(X-Api-Key 허용)으로 처리한다.
- body: `{"branches_of_project":"<프로젝트ID>","hidden":true|false}` — 그 프로젝트의 활성 브랜치 전부. 단건은 `{"branch_id":45,...}` 또는 `{"project":"branch:45"|"<프로젝트ID>",...}`.
- 유저별 설정(`recent_hidden` 테이블, 키=`project` 문자열). 숨겨도 브랜치는 살아 있고 전체 탭·검색에는 보인다. 숨김 이후 새로 만든 브랜치는 별도로 숨겨야 한다.
- 규칙(전역 프롬프트 `_petervoice_system`에 기재): 명시 지시 시에만, 처리 개수 보고, 숨긴 브랜치가 유저 결정이 필요한 질문을 하면 다시 노출하거나 링크로 안내.
