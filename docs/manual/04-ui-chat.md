# 04. 웹 UI — 채팅

## 핵심 컴포넌트

| 컴포넌트 | 파일 | 역할 |
|----------|------|------|
| ChatWindow | `components/ChatWindow.tsx` | 메인 채팅 컨테이너 |

## ChatWindow

메인 채팅 인터페이스. 프로젝트별 메시지 관리, Realtime 구독, 모달 관리를 담당.

### 기능

- **프로젝트별 메시지 로딩**: 프로젝트 전환 시 해당 프로젝트 메시지만 조회
- **Supabase Realtime 구독**: `messages` INSERT, `user_status` 변경 실시간 수신
- **자동 스크롤**: 새 메시지/스트리밍 시 하단으로 자동 스크롤
- **스크롤 다운 인디케이터**: 위로 스크롤한 상태에서 새 메시지 있으면 표시
- **프로젝트 활동 추적**: 각 프로젝트별 마지막 메시지, unread 상태
- **데몬 staleness 감지**: 60초+ 하트비트 없으면 오프라인 표시
- **모달 관리**: 설정, 문서, 시크릿, 프로젝트 선택 등 다중 모달
- **백버튼 트랩**: 모달 열린 상태에서 백버튼 → 모달 닫기 (로그아웃 방지)

### 스트리밍 텍스트

```
데몬 → POST /api/bot/reply (is_final=false)
  → user_status.streaming_text 업데이트
  → Supabase Realtime → 프론트엔드
  → 프로젝트별 스트리밍 텍스트 추출 → 실시간 표시
```

## MessageBubble

개별 메시지 렌더링. 사용자/봇 메시지를 구분하여 표시.

### 메시지 타입별 표시

| 타입 | 스타일 | 비고 |
|------|--------|------|
| user | 파란 배경, 우측 정렬 | |
| bot | 회색 배경, 좌측 정렬 | |
| bot + subtype='tool_log' | 접힌 상태, 작은 폰트 | 펼치기 가능 |

### 툴 로그 접기/펼치기

```
봇 메시지에 "🔧" 이모지 포함 → 툴 로그로 판별
  → 기본: 접힌 상태 "N개 도구 사용" 표시
  → 클릭: 펼쳐서 상세 내용 표시
  → 도구 사용 "중"에도 펼쳐보기 가능
```

### 링크 처리

- 마크다운 링크 `[text](url)` → 클릭 가능한 `<a>` 태그로 변환
- URL 자동 감지 → 클릭 가능 링크로 변환
- 괄호, 마크다운 기호가 URL에 포함되는 버그 수정 완료

### 스킬 액션 패턴

메시지 내 `[[네임스페이스/동작:payload]]` 구문 감지 → 자동 실행:

| 마커 | 동작 |
|------|------|
| `[[url/auto-open:https://...]]` | 자동 브라우저 오픈 |
| `[[command/reload:]]` | 페이지 리로드 |
| `[[phone/call:010-xxxx-xxxx]]` | 전화 걸기 오버레이 |
| `[[voice/handoff:프로젝트ID:맥락]]` | 음성 대화를 다른 프로젝트로 전환 |
| `[[browser/handoff:...]]` | 서버 브라우저 원격 로그인 인계 |
| `[[map/show:...]]` | 지도 패널 (아래 참조) |
| `[[docs/media:상대경로]]` | docs/ 산출물 인라인 표시 (아래 참조) |

**슬래시는 필수다.** `[[url:...]]` 처럼 쓰면 파서 화이트리스트에 안 걸리고, TTS 마커 제거
패턴(`lib/voice-utils.ts`)도 통과해 **음성이 마커를 그대로 읽는다.**

### docs 미디어 인라인 `[[docs/media:상대경로]]` (2026-09-02)

에이전트가 `docs/`에 만든 이미지·영상·오디오를 **유저가 문서탭에 가지 않고 채팅 말풍선 안에서
바로 보게** 하는 마커. 음성 fullscreen 모드에서는 지도처럼 화면 위에 도킹된다 (운전 중 확인용,
새로 도착한 봇 메시지에만 도킹 — 과거 이력은 도킹 안 됨).

```
영상을 만들었습니다. [[docs/media:media/demo.mp4]]
```

- 경로는 **docs/ 기준 상대경로** (`docs/` 접두를 붙여도 허용). `..`·절대경로는 무시된다.
- 확장자로 타입 판별: 이미지(png/jpg/gif/webp/svg 등)·영상(mp4/webm/mov)·오디오(mp3/wav/m4a 등).
  그 외 확장자는 "새 탭에서 열기" 링크로 폴백.
- 30MB 초과 파일도 인라인 대신 "새 탭에서 열기" 링크로 폴백된다 (현재 blob 전량 다운로드 방식).
  긴 영상은 시크(구간 이동)가 안 되므로 **1~2분 내 클립**이 적합하다.
- 마크다운 이미지 `![설명](docs/media/foo.png)` 도 말풍선 안에 인라인 렌더된다 (이미지 한정 —
  영상·음성모드 도킹이 필요하면 마커를 쓸 것).
- TTS는 마커·이미지 문법을 낭독하지 않는다 (자동 제거).

**에이전트 규칙**: 영상·이미지 산출물을 보고할 때 docs 경로만 적지 말고 이 마커를 응답에
붙여라 — 유저가 채팅에서 바로 확인한다.

### 지도 패널 `[[map/show:...]]`

대화 상단에 지도가 도킹된다. **음성 모드에서도 그대로 보인다** — 운전 중에 지도를 보면서
말로 대화하는 것이 이 기능의 목적이다.

페이로드는 두 형태다.

**1) URL 참조 (기본 — 경로가 있으면 반드시 이쪽)**

```
[[map/show:https://www.peter-voice.site/api/files/xxx/state.json]]
```

지도 상태 JSON 을 `/api/files/upload` 로 올리고 URL 만 넣는다. 경로 폴리라인은 코스 3개에
150KB 가 넘어 메시지 본문에 실을 것이 못 된다.

**2) 인라인 JSON (핀 몇 개짜리 소형만)**

```
[[map/show:{"pins":[{"name":"거송갈비찜 청주점","lat":36.68486,"lng":127.50611,"desc":"★4.78 · 소갈비찜 24,000"}]}]]
```

⚠️ **인라인에 `"path":[[36.1,128.3],...]` 같은 좌표 중첩 배열을 넣지 말 것.** 파서는 견디지만
가독성·크기 모두 나쁘다. 경로는 URL 참조를 쓰거나, 굳이 인라인이면 `path` 를 Google encoded
polyline **문자열**로 넣는다.

#### 스키마

```jsonc
{
  "id": "route-food",        // 같은 id 면 기존 패널을 갱신 (지도 하나만 유지)
  "title": "갈비찜 후보",     // 패널 좌상단 라벨
  "focus": { "lat": 36.68, "lng": 127.5, "zoom": 9 },  // 없으면 전체 fitBounds
  "height": 320,             // px, 기본 320
  "mylocation": true,        // GPS 켜고 위치를 다음 메시지에 자동 첨부

  "routes": [{
    "key": "A", "label": "중부내륙 · 충주 코스",
    "color": "#e53935", "weight": 6, "dash": "6,8",   // dash = 점선(밀린 후보). color 는 segments 없을 때·정체값 없는 구간의 색
    "min": 261, "km": 283,
    "path": [[36.1, 128.3], [36.2, 128.4]],           // 또는 encoded polyline 문자열 (segments 가 있으면 생략 가능)
    "segments": [                                      // ★ 정체 단계별 구간 — 내비처럼 원활=초록 · 서행=주황 · 정체=빨강
      { "path": "encoded…", "congestion": 1 },         //   congestion: 0/1 원활, 2 서행, 3 정체
      { "path": "encoded…", "congestion": 3 }          //   네이버 Directions 응답 route.*[].section[].congestion 을 그대로 넘기면 된다
    ],                                                 //   (경로를 색별로 여러 routes 로 쪼개지 말 것)
    "markStep": 60,                                    // 시간 눈금 간격(분), 기본 60
    "marks": [{ "min": 60, "lat": 36.11, "lng": 128.37, "name": "김천 아포" }],
    "visible": false                                   // 숨김
  }],

  "pins": [{                 // "pois" 도 같은 뜻으로 받는다
    "name": "거송갈비찜 청주점", "lat": 36.68486, "lng": 127.50611,
    "eta": "14:55",          // ★ 도착 예정 시각 — 라벨에 "14:55 거송갈비찜 청주점" 으로 자동 표시
    "color": "#1e88e5",
    "desc": "★4.78 리뷰1,518<br/>소갈비찜 24,000",   // b/strong/em/i/small/br 만 허용
    "link": "https://m.place.naver.com/restaurant/1575131397/home"
  }]
}
```

#### 추천 코스 지도의 기본 구성 (2026-08-30 Sean 확정)

이동 중 "가는 길에 뭐 먹을까" 류 요청에 띄우는 지도는 **항상 아래 세 가지를 갖춘다.**

1. **현재위치 → 목적지 경로선** — `routes[0]` 에 `segments` 로 정체 색 포함 (`mylocation: true`)
2. **경로 위 추천 핀** — 각 핀에 `eta` (그 지점 도착 예정 시각). 라벨은 "14:55 경남식당" 으로 자동
3. 같은 `id` 로 갱신 — 유저 위치가 바뀌거나 후보를 바꿀 때 새 지도를 띄우지 않고 갱신한다

```jsonc
{
  "id": "route-food", "title": "죽도 → 경북대병원 · 점심", "mylocation": true,
  "routes": [{ "key": "A", "label": "영동→중앙고속도로", "min": 244, "km": 329,
               "segments": [{ "path": "…", "congestion": 1 }, { "path": "…", "congestion": 2 }] }],
  "pins": [{ "name": "봉화산설렁탕 (원주)", "lat": 37.345, "lng": 127.945, "eta": "14:01", "desc": "갈비탕 17,000" },
           { "name": "경북대병원 장례식장", "lat": 35.866, "lng": 128.605, "eta": "17:18", "desc": "목적지" }]
}
```

경로가 있으면 URL 참조로 올린다(위 "URL 참조" 참고). 라벨이 겹치면 뒤 순서 핀은 점으로 축약되고
탭하면 이름이 뜨므로, **중요한 핀을 pins 앞쪽에** 둔다.

#### GPS

`"mylocation": true` 면 위치 공유가 켜지고(브라우저 권한 프롬프트), 이후 유저가 보내는
메시지 끝에 좌표가 자동으로 붙는다.

```
지금 어디쯤이야?

(현재 위치: 36.12345, 128.34567 ±25m)
```

**위치를 알면 선택지가 줄어든다** — "C 대전 코스는 이미 11km 벗어나 끝났고, 남은 건 A 와 B"
같은 판단이 가능해진다. 이동 중 대화에선 이게 지도를 그리는 것보다 가치가 크다.

좌표는 20초에 한 번만 갱신되고, 5분 넘게 갱신이 없으면 첨부하지 않는다(이동 중엔 이미
틀린 값이라서). 유저가 패널의 `📍` 칩이나 `닫기` 로 언제든 끌 수 있다.

### 파일 첨부 렌더링

- **이미지**: 인라인 프리뷰 (max-height 240px)
- **일반 파일**: 📎 아이콘 + 파일명 + 크기
- **자동 오픈 URL**: 초록색 버튼 (외부 링크 아이콘)

### TTS (텍스트 음성 변환)

각 봇 메시지에 스피커 버튼:
1. 마크다운 제거 (코드 블록, 링크, 볼드 등)
2. 문장 단위로 분할 (한국어/영어 구두점)
3. 각 청크 → POST /api/tts/generate → MP3 재생
4. 볼륨: 스피커 모드 (음성모드와 동일 레벨)

### 타이밍 정보

메시지에 표시:
- 폴 딜레이: 메시지 생성 → 데몬 fetch 시간
- 처리 시간: fetch → 응답 완료 시간

## MessageInput

텍스트 + 파일 입력 인터페이스.

### 입력 방식

- **텍스트**: textarea (자동 높이 조절, 최대 120px)
- **Enter 전송**, Shift+Enter 줄바꿈
- **파일 첨부**: 버튼 클릭, 드래그 앤 드롭, 클립보드 붙여넣기 (Ctrl+V)
- **외부 텍스트 삽입**: 문서/할일에서 "@문서명" 삽입

### 파일 업로드 프로세스

```
파일 선택 → 프리뷰 표시 (제거 가능)
  ↓ 전송 시
POST /api/files/upload (JSON 모드) → signed URL 발급
  ↓
PUT (Supabase Storage 직접 업로드) → Vercel 4.5MB 제한 우회
  ↓
메시지에 파일 메타데이터 포함하여 전송
```

- 최대 파일 크기: 50MB
- 업로드 에러: 5초 자동 해제 플래시 메시지

### 상태별 버튼

| 상태 | 버튼 |
|------|------|
| 기본 | 전송 (파란색) |
| 봇 작업 중 | 중지 (빨간색) |
| 파일 대기 중 | 전송 (파일 수 표시) |

## 자동 스크롤 동작

```
새 메시지 수신 시:
  → 사용자가 하단 근처에 있으면 → 자동 스크롤
  → 사용자가 위로 스크롤했으면 → "새 메시지" 인디케이터 표시

툴 사용 중 (스트리밍):
  → 메시지 버블 내부에 스크롤바 생기지 않음 (버블 자체가 커짐)
  → 외부 스크롤 자동 하단 이동

스트리밍 텍스트:
  → 2초마다 업데이트 → 자동 스크롤
```

## 헤더 UI 구조

채팅 헤더는 **1단 구조**로 정리되어 있다 (기존 2단 14개 요소에서 단순화됨).

### 주요 변경사항
- **메시지 선택**: 헤더 아이콘 제거 → 메시지 버블 hover 시 체크박스 표시 + 하단 액션 바
- **세션 메뉴**: 헤더 아이콘 제거 → 상태 점(●) 클릭 패널로 이동
- **칸반**: 헤더 아이콘으로 직접 접근 (기존 할일 위치)
- **할일**: ⋯ 드롭다운 메뉴 안으로 이동

## 메시지 선택 모드

- **진입**: 메시지 버블 hover 시 체크박스 표시
- **선택**: 체크박스 클릭
- **액션**: 하단 액션 바에서 복사, 삭제 등
- (기존 헤더 아이콘 + 라디오 버튼 방식에서 변경)

## 마크다운 렌더링 개선

### 줄바꿈

`remark-breaks` 플러그인을 사용하여 **엔터 1번 = 줄바꿈**으로 동작. 기존에는 마크다운 표준에 따라 엔터 2번이 필요했으나, 채팅 환경에 맞게 변경.

### Mermaid 다이어그램

마크다운 내 ````mermaid` 코드 블록을 SVG 다이어그램으로 자동 렌더링.

- **웹앱** (`DocumentsPanel.tsx`): mermaid npm 패키지 + dynamic import
- **홈포탈** (`home-portal.js`): mermaid CDN + `marked.parse()` 후 변환
- 지원 다이어그램: flowchart, sequence, class, state, ER, gantt, pie 등
